## Decisions made
- **React panes now carry the JSF panel classes** (`siamois-panel <entity>-panel single-panel|list-panel`) computed from what each pane shows *now* (`App.tsx paneClassName`, `EntityTypeConfig.panelClass`). Before, the main pane inherited the class of the entity JSF *mounted* (wrong colours after a client-side navigation) and the overview pane inherited the *main* entity's colours.
- Detail tab titles now use JSF's `tabTitle.xhtml` markup (bold `label (count)`) instead of a grey Chip; list header count chip gets the JSF `<entity>-count-chip` class.
- `primereact/resources/primereact.min.css` import removed: it is an empty deprecated stub (PrimeReact 10 injects structural CSS at runtime in `@layer primereact`).
- **Theming mechanism = Sass `@extend` class aliases + hand-written pseudo-states.** `.p-x { @extend .ui-x }` makes every existing rule that mentions `.ui-x` (theme-base AND siamois overrides) also emit `.p-x`, without touching the `.ui-*` output. Pseudo-class states (`:hover`, `:focus-visible`) are NOT extended: measured, that inflates the theme to 1 MB minified / 79 KB gzip. Class states (`.p-highlight`, `.p-focus`, `.p-invalid`) ARE extended (+4 KB gzip) so the app's own state overrides carry over.
- Size: theme.css 298 KB → ~600 KB minified, **+21 KB gzip**; Lara (224 KB / 21 KB gzip) is no longer shipped by the bundle ⇒ net transfer ≈ 0.
- `settings.css` is a separate compilation: aliases it needs are declared in `settings.scss` itself (only `.p-tabview-nav` so far).
- JSF non-regression is verified mechanically: `frontend/dev/check-jsf-theme-regression.sh [ref]` (only diff vs HEAD = the intended @font-face URL fix).
- API report written in English for the external contractor; internal endpoints (`/api/auth/session-token`, `/api/context/check`) listed separately as 'ignore'.
- Counted `answers` omission on RU list items (was always `{}`) as breaking, since strict clients may rely on the key.
